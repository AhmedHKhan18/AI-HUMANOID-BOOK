# Implementation Plan: Enhanced Authentication System with Better Auth

**Branch**: `002-better-auth` | **Date**: 2025-12-20 | **Spec**: [spec.md](./spec.md)
**Input**: Feature specification from `/specs/002-better-auth/spec.md`

## Summary

Implement a production-ready authentication system for the Docusaurus documentation site using Better Auth library with Neon DB (PostgreSQL) storage. The system provides email/password authentication with verification, session management with activity-based refresh, password reset, and profile management. Architecture separates Docusaurus (static frontend) from an Express.js API server handling Better Auth endpoints.

---

## Technical Context

**Language/Version**: TypeScript 5.x, Node.js 18+
**Primary Dependencies**: Better Auth ^1.0, Drizzle ORM ^0.30, Express ^4.18, React 18
**Storage**: Neon DB (PostgreSQL serverless) via @neondatabase/serverless
**Testing**: Vitest for unit tests, Playwright for E2E
**Target Platform**: Web (Docusaurus 3.0 static site + Express API)
**Project Type**: Web application (static frontend + API backend)
**Performance Goals**: <2s login response, <10s full page load with auth state
**Constraints**: Docusaurus SSG limitations (no native API routes), CORS handling required
**Scale/Scope**: Hundreds of concurrent users, single database instance

### Phase 1: Foundation Setup

**Goal**: Establish project infrastructure and database connectivity

**Tasks**:
1. Create `api/` directory structure
2. Initialize API package.json with TypeScript
3. Install core dependencies (better-auth, drizzle-orm, @neondatabase/serverless)

**Deliverables**:

## Risk Assessment

| Risk | Probability | Impact | Mitigation |
|------|------------|--------|------------|
| Neon DB cold starts | Medium | Medium | Connection pooling, keep-alive pings |
| Email delivery delays | Medium | Low | Queue with retry, user notification |
| CORS misconfig | High | High | Explicit origin config, thorough testing |
| Session sync across tabs | Low | Low | Cookie-based sessions, polling |
| Docusaurus SSG limitations | Low | Medium | Separate API architecture (resolved) |
| Better Auth version changes | Low | Medium | Pin version, test upgrades in staging |

## Complexity Tracking

> No constitution violations requiring justification.

| Decision | Rationale | Simpler Alternative Considered |
|----------|-----------|-------------------------------|
| Separate API server | Docusaurus lacks native API routes | Swizzled plugin (too complex, unsupported) |
| Drizzle ORM | Type-safe, Better Auth native adapter | Raw SQL (loses type safety) |
| Email queue table | Spec requires retry on failure | In-memory queue (loses state on restart) |
